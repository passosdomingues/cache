O Projeto BlueVelvet Music Store

Este resumo integra os conceitos do papel do Product Owner com o desenvolvimento prático da BlueVelvet Music Store, uma loja online de música com módulos para Administradores e Compradores.

1. A Preparação do Líder (Papel do Product Owner - PO)

A primeira grande missão foi capacitar quem iria gerenciar o projeto no papel de Product Owner. A equipe mergulhou em um curso completo sobre o assunto, assistindo a uma série de vídeos (do 1 ao 23). O objetivo era claro: entender como priorizar as funcionalidades da loja (como os módulos de Administrador e Comprador online) e garantir que o time de desenvolvimento estivesse sempre focado no que era mais importante para o projeto. Esse conhecimento foi a base para guiar todo o desenvolvimento.

Papel do Product Owner (Clique para revelar)
O PO é responsável por maximizar o valor do produto através do gerenciamento do Product Backlog. Ele define o "o quê" e o "porquê", enquanto o time de desenvolvimento define o "como".

2. Montando a Oficina: O Ambiente de Desenvolvimento

Enquanto o PO se preparava, os desenvolvedores colocavam a "mão na massa" para montar seu ambiente de trabalho. Esta fase foi crucial e envolveu vários passos:

A Fundação: Java (JDK)

Tudo começa com a instalação do JDK (Java Development Kit), o coração do projeto. A equipe baixou, instalou e configurou o JDK, testando com o clássico "Hello World" para garantir que estava tudo funcionando. É a ferramenta básica para escrever o código da loja.

O Construtor: Apache Maven

Em seguida, veio o Maven. Imagine que, em vez de montar um quebra-cabeça peça por peça manualmente, você tem uma máquina que monta seções inteiras para você. O Maven é essa ferramenta que automatiza a compilação e o gerenciamento das dependências do projeto, agilizando muito o trabalho.

O Banco de Dados: MySQL

Uma loja precisa de um estoque, certo? No mundo digital, o estoque é o banco de dados. A equipe instalou o MySQL, criou um banco de dados e aprendeu a manipulá-lo tanto pela linha de comando quanto por interfaces gráficas como o MySQL Workbench e PHPMyAdmin, que facilitam a visualização dos dados.

3. Populando o Banco de Dados

Com o banco de dados pronto, era hora de criar a estrutura e os dados iniciais para testes. Foram escritos scripts SQL (arquivos com comandos) para criar tabelas essenciais:

Tabelas de Usuário e Permissões (USER, ROLE, ROLE_USER)

Para gerenciar quem acessa o sistema e o que cada um pode fazer (como Administrador, Gerente de Vendas, etc.). Foi criada uma relação "muitos-para-muitos", onde um usuário pode ter vários cargos.

Tabela de Produtos (Product)

Para cadastrar os itens à venda na loja, como CDs e vinis. Esses scripts garantiram que a equipe teria dados realistas para testar as funcionalidades enquanto desenvolve.

4. Controlando o Código-Fonte: Git

Desenvolver um software em equipe exige controle sobre as alterações no código. É aí que entra o Git, um sistema de versionamento. A equipe:

  • Instalou e configurou o Git em suas máquinas.
  • Estudou profundamente seus comandos através de uma série de screencasts, aprendendo a salvar versões do código (commit), criar ramificações para novas funcionalidades (branch) e integrar o trabalho de todos sem conflitos.

5. Conectando o Sistema ao Banco: JPA

Por fim, a equipe começou a estudar a Jakarta Persistence API (JPA), uma tecnologia que permite que o código Java (o sistema da loja) se comunique de forma eficiente e organizada com o banco de dados MySQL. Em vez de escrever comandos SQL complexos manualmente, o JPA ajuda a "mapear" os objetos do código para as tabelas do banco, simplificando muito a persistência dos dados. O estudo focou nas partes I e II de um material prático, preparando o terreno para a implementação.

Resumo dos Pontos-Chave (O que Cairá na Prova)

Pontos-Chave para a Prova (Clique para revelar)
  • Product Owner (PO): Papel responsável por definir o "o que" será feito
  • JDK: Ferramenta fundamental para desenvolver em Java
  • Maven: Ferramenta de automação que gerencia o build do projeto
  • MySQL: Sistema de gerenciamento de banco de dados relacional
  • Git: Sistema de controle de versão
  • JPA: Especificação para mapeamento objeto-relacional
  • Scripts SQL: Arquivos para criar e popular tabelas no banco
